# MATARI v0.1 UX 상태 명세

- 상태: 구현 기준선
- 최종 갱신: 2026-09-18
- 상위 문서: [MATARI v0.1 제품 기획](product-plan-v0.1.ko.md)
- 범위: macOS 메뉴바 표시, 사용량 팝업, 최소 설정, 오류 및 데이터 상태

## 1. 목적

### 2026-09-24 계정 quota 조회 추가

아래의 과거 서버 조회 제외 방침을 변경한다. 시작·30분 주기·수동 새로고침·잠자기
복귀 시 설치된 Codex App Server로 계정 잔여율을 조회한다. 같은 값도 새 관측으로
저장하며 실패는 별도 안내하고 기존 수치를 보존한다. 로컬 토큰 집계는 그대로 유지한다.
세부 동작과 제약은 [주기 조회 설계](quota-polling.ko.md)를 따른다.

### 2026-09-18 사용자 피드백 반영

아래 기존 수동 갱신 제외 방침을 변경한다. 헤더에 로컬 기록 새로고침 버튼을 제공하며,
서버 quota를 요청하는 기능이 아니라는 설명을 tooltip에 표시한다. 파일 감시와 패널 열기
외에 60초마다 증분 재스캔하고, 스캔 중 감지한 변경은 종료 후 재처리한다.
보조 텍스트는 primary 색상의 75% 불투명도로 대비를 높인다. 패널은 ultra-thin material을
사용하며 ‘투명도 줄이기’ 설정에서는 시스템 불투명 배경을 사용한다.
설정의 뒤로 가기는 화살표와 ‘설정’ 제목을 포함한 최소 80×32pt 버튼으로 제공한다.
메뉴바는 배터리 잔량과 혼동하지 않도록 `Codex 100%`처럼 이름을 함께 표시한다.
두 버킷이면 `Codex 63% · 27%`로 표시한다.

이 문서는 정상 화면 이외의 모든 주요 상태에서 MATARI가 무엇을 표시하고 어떻게 동작해야 하는지 정의한다. 구현은 숫자를 추정해 빈칸을 채우는 것보다, 관측할 수 없는 상태를 정직하게 표현하는 것을 우선한다.

## 2. 확정된 기본 UI

- 메뉴바: 단색 MATARI 심볼 + 잔여 퍼센트
- 여러 제한: 짧은 제한 창부터 `63% · 27%` 형식으로 표시
- 제한 이름 축약: 메뉴바에서는 표시하지 않음
- 패널 폭: 336pt
- 섹션: 구분선형
- 브랜드 노랑: `#F6C945`
- 진행 막대 노랑: `#D3A62A`
- 패널: `MenuBarExtra`의 window 스타일
- 독립 창 및 항상 보기: v0.1 제외

## 3. 상태 판정 원칙

### 3.1 시간이 지났다는 이유만으로 데이터를 오류로 만들지 않는다

Codex가 작업 중이 아니면 새 세션 이벤트가 없는 것이 정상이다. 마지막 갱신 후 시간이 오래됐다는 사실만으로 quota 값을 폐기하거나 오류 색상으로 표시하지 않는다.

대신 마지막 유효 스냅샷의 시각을 항상 보여준다.

- 1분 미만: `방금 전 갱신`
- 1시간 미만: `N분 전 갱신`
- 24시간 미만: `N시간 전 · Codex 비활성`
- 24시간 이상: `N일 전 · Codex 비활성`

### 3.2 reset 시각이 지난 버킷은 현재값으로 취급하지 않는다

현재 시각이 `resets_at` 이상이고 reset 이후 새 스냅샷이 없다면 해당 퍼센트는 더 이상 현재값이 아니다.

- 메뉴바: 해당 버킷을 숨김
- 다른 유효 버킷이 있으면 그것만 표시
- 유효 버킷이 하나도 없으면 `–` 표시
- 패널: 퍼센트 대신 `확인 중` 표시
- 보조 문구: `초기화 후 새 데이터 대기 중`
- 100%로 임의 복원하지 않음

### 3.3 부분 실패는 정상 데이터까지 숨기지 않는다

quota가 없지만 토큰이 있으면 토큰을 표시한다. 한 버킷만 유효하면 해당 버킷만 표시한다. 한 JSONL 행이 손상돼도 이전의 마지막 유효 상태는 유지한다.

## 4. 메뉴바 상태

| 상태 | 표시 | 동작 |
|---|---|---|
| 앱 시작 및 초기 스캔 | `심볼 …` | 클릭 시 로딩 화면 |
| 제한 두 개 | `심볼 63% · 27%` | 짧은 창 → 긴 창 순서 |
| 제한 한 개 | `심볼 27%` | 존재하는 값만 표시 |
| 유효 quota 없음 | `심볼 –` | 클릭 시 원인 표시 |
| Codex 경로 없음 | `심볼 !` | 클릭 시 경로 선택 안내 |
| 지속적인 읽기 오류 | `심볼 !` | 클릭 시 오류와 재시도 제공 |
| reset 후 새 데이터 대기 | 유효 버킷만 표시, 전부 만료 시 `심볼 –` | 과거 퍼센트 숨김 |

메뉴바 텍스트에는 색상으로 경고를 표시하지 않는다. macOS template 아이콘과 시스템 텍스트 색상을 따른다.

## 5. 패널 상태

### 5.1 정상

- 동적으로 존재하는 제한 섹션
- 잔여율과 진행 막대
- 초기화 절대시각
- 초기화까지 남은 시간
- 오늘/이번 주 로컬 토큰
- 오늘/이번 주 `1%당 토큰`
- 마지막 갱신
- 설정 버튼
- `MATARI 종료`

### 5.2 초기 스캔

표시:

```text
Codex 사용 기록 읽는 중…
```

- 시스템 `ProgressView` 사용
- 과거 파생 데이터가 있으면 이전 화면을 유지하고 footer에 `새 데이터 확인 중…` 표시
- 최초 실행으로 캐시가 없을 때만 전체 로딩 화면 표시

### 5.3 제한 버킷이 하나만 존재

- 존재하지 않는 버킷의 빈 자리나 `없음` 행을 만들지 않음
- 단일 제한 섹션 다음에 바로 로컬 토큰 섹션 배치
- 패널 높이는 내용에 맞게 줄어듦

### 5.4 quota 없음, 토큰 있음

quota 영역에 한 줄 상태를 표시한다.

```text
사용 한도 데이터 없음
Codex가 새 사용량 정보를 기록하면 자동으로 표시됩니다.
```

로컬 토큰 영역은 정상적으로 표시한다.

### 5.5 reset 후 새 데이터 대기

해당 제한 섹션을 유지하되 값을 다음처럼 바꾼다.

```text
주간 제한
남음                         확인 중
초기화 후 새 데이터 대기 중
```

- 진행 막대 숨김
- 이전 퍼센트는 표시하지 않음
- 다음 유효 스냅샷이 들어오면 정상 상태로 자동 복귀

### 5.6 Codex 비활성

- 마지막 유효 퍼센트가 reset 이전이면 그대로 표시
- 경고색을 사용하지 않음
- footer에 `2시간 전 · Codex 비활성`처럼 표시
- 별도의 알림이나 오류 배너를 만들지 않음

### 5.7 Codex 경로를 찾지 못함

```text
Codex 사용 기록을 찾을 수 없습니다
기본 위치에서 세션 폴더를 찾지 못했습니다.

[폴더 선택]
```

- 인증 파일을 요구하지 않음
- 사용자가 `CODEX_HOME` 또는 그 아래의 세션 폴더를 선택할 수 있음
- 잘못된 폴더면 필요한 구조를 찾을 수 없다고 설명

### 5.8 세션 파일 없음

```text
아직 기록된 Codex 사용량이 없습니다
Codex를 사용하면 여기에 자동으로 표시됩니다.
```

- 오류로 취급하지 않음
- 재시도 버튼 없음
- 파일 감시는 계속 유지

### 5.9 읽기 오류

일시적인 partial write와 지속적인 파일 접근 오류를 구분한다.

- 마지막 미완성 JSONL 행: UI에 오류를 노출하지 않고 다음 쓰기에서 재시도
- 개별 손상 행: 건너뛰고 진단 로그에 익명화된 위치만 기록
- 전체 경로 접근 실패: 기존 데이터를 유지하고 footer에 `사용 기록을 읽을 수 없음` 표시
- 사용자가 할 수 있는 조치가 있을 때만 `다시 시도` 또는 `폴더 다시 선택` 제공

## 6. 진행 막대와 경고

잔여량이 충분할 때는 확정된 진행 막대 노랑 `#D3A62A`를 사용한다.

| 잔여율 | 표현 |
|---:|---|
| 21~100% | 진행 막대 노랑 |
| 11~20% | 시스템 주황색 + 퍼센트 텍스트 |
| 0~10% | 시스템 빨간색 + 퍼센트 텍스트 |

- 색상만으로 상태를 전달하지 않음
- 별도의 경고 문장이나 알림은 v0.1에서 사용하지 않음
- progress animation은 값이 새로 갱신될 때만 짧게 적용
- Reduce Motion이 활성화되면 animation 비활성화

## 7. 토큰 표시

### 7.1 숫자 형식

- 1,000 미만: 정수
- 1,000 이상: `1.2K`
- 1,000,000 이상: `1.2M`
- 1,000,000,000 이상: `1.82B`
- 유효값 0: `0`
- 계산 불가: `–`
- 숫자는 monospaced digit 사용

표시 자릿수는 최대 유효 숫자 3자리 수준으로 제한하되, `1.82B`처럼 비교에 필요한 정밀도는 유지한다.

### 7.2 `1%당 토큰`

2026-09-20 계산 수정: 현재 장기 버킷의 요금제와 초기화 구간 안에서만 계산한다.
2026-09-21 보완: 현재 버킷은 초기화 시각의 최댓값이 아닌 최신 유효 관측으로 선택한다.
관측 당시 이미 만료된 기간의 지연 기록은 제외한다. 잔여율과 비율 계산 모두 선택된
초기화 시각 기준 ±60초를 같은 구간으로 취급하며 연쇄적으로 범위를 넓히지 않는다.
이는 서버 보장이 아닌 로컬 기록의 시각 흔들림에 대한 앱의 휴리스틱이다. 허용폭 밖의
기록도 최신이면 표시 대상으로 선택되지만 이전 구간의 사용률과 합치지 않는다.
오늘/이번 주 경계 이후의 첫 관측부터
마지막 관측까지 high-water 증가분이 1%p 이상이면 같은 구간의 토큰 `(첫 관측, 마지막 관측]`을
나눈다. 시작 사용률을 0으로 추정하지 않는다. 전체 토큰 합계는 달력 기간 전체를 유지한다.
요금제 변경·초기화 전후를 섞지 않으므로 비율의 대상 기간은 전체 합계보다 짧을 수 있다.

- 장기 제한 버킷을 기준으로 계산
- 연속된 관측 구간에서 quota 감소가 최소 1퍼센트포인트 있어야 표시
- 조건 미충족: `계산 중`
- 계산 성공: `≈ 39.1M`
- quota reset 또는 불연속 구간에서는 새 계산 epoch 시작
- 항상 `≈`를 붙임
- 섹션 제목의 `이 Mac에서 관측` 문구로 로컬 근사치임을 상시 알림

## 8. 시간 갱신

- 파일 이벤트 수신: 즉시 파싱 예약
- 여러 파일 이벤트: 짧은 debounce 후 한 번에 처리
- panel 열기: 즉시 경로와 최신 offset 재검사
- reset countdown: 1분마다 화면만 갱신
- 날짜 경계: Asia/Seoul 기준 자정에 오늘 집계 전환
- 주 경계: Asia/Seoul 기준 월요일 00:00에 이번 주 집계 전환
- 서버에 수동 quota 요청을 보내지 않음

## 9. 수동 새로고침

정상 화면에는 새로고침 버튼을 두지 않는다.

- 파일 감시로 자동 갱신
- 패널을 열 때 최신 상태 재검사
- 오류 상태에서만 `다시 시도` 제공

사용자가 누르면 서버의 quota가 갱신되는 것처럼 오해할 수 있으므로 일반 새로고침 버튼은 제공하지 않는다.

## 10. 첫 실행

1. 기본 `CODEX_HOME` 탐색
2. 세션 경로가 있으면 별도 onboarding 없이 즉시 스캔
3. 첫 스캔 중 로딩 상태 표시
4. 경로가 없으면 폴더 선택 안내
5. 성공 후 `이 Mac의 로컬 사용 기록만 읽습니다`를 한 번 안내

긴 튜토리얼, 계정 로그인, 개인정보 동의 화면은 만들지 않는다.

## 11. 설정

설정은 별도 창이 아니라 메뉴바 패널 안에서 같은 크기의 설정 화면으로 전환한다. 왼쪽 위의 뒤로 가기로 사용량 화면에 복귀한다.

### 포함

- `로그인 시 MATARI 실행` 토글
  - 기본값: 꺼짐
  - 사용자가 명시적으로 켜야 함
- Codex 데이터 경로
  - 현재 자동 탐색 경로 표시
  - `폴더 선택`
  - `기본값으로 재설정`
- 개인정보 안내
  - 대화 본문과 인증 정보는 저장하지 않음
- 앱 버전 및 오픈소스 링크 자리

### 제외

- 색상과 테마 선택
- 갱신 주기 설정
- quota 버킷 선택
- 주 시작 요일 설정
- 알림 설정
- 데이터 export

## 12. 종료

- footer 오른쪽에 `MATARI 종료` 텍스트 버튼 유지
- 선택 즉시 앱 종료
- 확인 대화상자를 표시하지 않음
- 파생 데이터는 삭제하지 않음

## 13. 접근성

- 메뉴바 VoiceOver: `MATARI, 5시간 제한 63퍼센트 남음, 주간 제한 27퍼센트 남음`
- 진행 막대: 제한 이름과 잔여율을 접근성 값으로 제공
- 설정과 종료는 명확한 텍스트 또는 접근성 이름 제공
- 경고는 색상과 퍼센트 텍스트를 함께 사용
- 키보드로 모든 버튼과 설정에 접근 가능
- Reduce Motion 존중
- 라이트·다크 모드 모두 시스템 대비 기준 유지

## 14. 상태 전환 요약

```text
시작
  └─ 경로 탐색
      ├─ 경로 없음 → 폴더 선택
      └─ 경로 있음 → 초기 스캔
          ├─ 기록 없음 → 빈 상태 + 파일 감시
          ├─ 일부 데이터 → 존재하는 섹션만 표시
          └─ 정상 데이터 → 사용량 패널

사용량 패널
  ├─ 새 파일 이벤트 → debounce → 파싱 → 화면 갱신
  ├─ Codex 비활성 → 마지막 값 유지 + 갱신 시각 표시
  ├─ reset 통과 → 해당 값 확인 중 → 새 snapshot 대기
  ├─ 경로 접근 실패 → 이전 값 유지 + 오류 상태
  └─ 설정 → 같은 패널 안에서 설정 화면으로 전환
```

## 15. UX 완료 조건

1. 정상·단일 버킷·quota 없음 상태에서 레이아웃이 깨지지 않는다.
2. reset 이후 이전 퍼센트를 현재값처럼 표시하지 않는다.
3. 단순 비활성을 오류로 오인하지 않는다.
4. 사용자가 서버 갱신으로 오해할 수 있는 새로고침 버튼이 없다.
5. 계산할 수 없는 값은 `계산 중` 또는 `–`로 일관되게 표시한다.
6. 경로 오류에서 사용자가 취할 수 있는 조치가 명확하다.
7. 설정과 사용량 화면을 별도 앱 창 없이 오갈 수 있다.
8. 모든 핵심 상태를 VoiceOver와 색상 외 정보로 구분할 수 있다.
